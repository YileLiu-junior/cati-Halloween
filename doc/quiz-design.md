## 2. 属性系统（结果卡展示用，不参与匹配）

六条属性轴，每条 0~10 分（5 为中间值），随选项加减：

| 轴 | 名称 | 低段（→0） | 高段（→10） | 计分选项数 |
|---|---|---|---|---|
| E | 电量 | 安静充电、睡神附体 | 电量爆炸、跑酷狂魔 | 8 |
| A | 贴贴 | 高冷独立、保持距离 | 分秒黏人、贴贴怪 | 8 |
| B | 胆量 | 谨慎小怂、先躲为敬 | 天不怕地不怕 | 7 |
| D | 戏精 | 淡定面瘫、波澜不惊 | 戏精附体、表情包本包 | 6 |
| F | 干饭 | 挑食矜持、浅尝辄止 | 胃是无底洞 | 4 |
| C | 好奇 | 生人勿近、懒得理你 | 什么都要研究一下 | 7 |

- 结果卡画**六边形雷达图**（六轴刚好），展示"你家猫的属性条"。
- 已知取舍：F−（挑食）和 C−（懒得理）的计分选项各只有 1 个，真实猫的 F/C 均分会偏高——只影响展示不影响匹配，可接受；上线后想调可加题。

## 3. 匹配算法（角色加分制）

**每个选项直接给若干角色加分**（主 +2，签名选项 +3，副 +1），答完 10 题取总分最高的角色。平局按固定优先顺序取先者。

```js
// 伪代码
const scores = {};            // 16 个角色, 初始 0
const axes   = {E:5,A:5,B:5,D:5,F:5,C:5};   // 属性展示用
for (const pick of answers) {
  axes[pick.axis] += pick.delta;
  for (const [cid, pts] of pick.charPoints) scores[cid] += pts;
}
const winner = TIE_BREAK.find(cid => scores[cid] === Math.max(...Object.values(scores)));
```

**上线必须做的两件事**（平衡验证的前提）：

1. **每题的 4 个选项随机排序**后再展示——角色加分和选项位置的绑定就无所谓了，"用户总选第一个"的偏好不再影响结果分布（已用模拟验证）。
2. 题目本身顺序也可以每题打乱（可选）。

**为什么不用"属性→最近角色"的距离匹配**：实测调不平——独立系角色（吸血鬼/法老/石像鬼）在随机模拟里只有 0.2%~1.7% 的占比，怎么调属性面板都压不平（数值几何问题，不是文案问题）。直接加分制两轮就调平了，且每条"选项→角色"的连接都是人工写的，梗更准。

## 6. 生图 Prompt（16 条，火山方舟 Seedream 4.0 图生图用）
