# 喵灵万圣节：技术说明与开发交接补充

日期：2026-10-26。配套 [交互规格 v1.1](interaction-design.md)。本项目只维护方案，不创建产品代码或部署资源。

【原文证据】用户已确认：北京时间 2026-10-31 00:00 前 2 元，此后 5.9 元；显示时分秒倒计时；取消装饰动画；技术失败最多两轮，成功但不像不人工补生；用户打 1–5 分、低分可申请退款，24 小时内核实；两档同水印、无早鸟角标，传播名“喵灵万圣节”。

【跨源综合】平台能力以下列官方资料为依据。小程序收款、抠图模型和删除规则都有边界，不能按旧经验假设可用。

【模型补充】接口、布局、安全留白和周期是本次设计建议，尚未经过实现或真机验证；候选供应商不等于已经选定或付费开通。

## 1. localStorage、KV、R2 各是什么

| 名称 | 在哪里／是什么 | 本产品保存什么 | 限制 |
|---|---|---|---|
| localStorage | 用户当前浏览器内置的数据存储 | 答到第几题、答案、选项顺序、找回口令、最近结果 | 换浏览器/域名不互通；清缓存可能丢失；用户可改，不能据此认定已付款 |
| KV | Cloudflare 云端的键值存储 | testId 对应结果、订单和任务状态、评分/退款申请、图片编号 | 短时间跨地区可能读到旧值；不适合仅靠读后写来扣次数 |
| R2 | Cloudflare 的对象存储，保存文件字节 | 原照、生成图、透明主图，以及少量原子领取凭证 | 必须私有；访问需鉴权；存储、读写有配额和费用 |

浏览器记录提升续答体验；云端记录负责恢复和核验；图片放 R2，不把大图塞进 KV/localStorage。身份以私密找回口令校验，晒卡上的公开 ID 不能领取订单。localStorage 的隔离单位是 origin，具体见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)；KV 的并发限制见 [官方说明](https://developers.cloudflare.com/kv/api/write-key-value-pairs/)。

**七天生命周期**是存储中的自动删除规则，不是另一家服务。需要更正 v1.0 的简写：R2 官方说对象通常在过期时间后 24 小时内删除，不能只配规则就承诺第七天准时物理删除。方案为：接口到期立即禁止读取，后台主动删除并核验，生命周期兜底；只清理图片前缀，不误删未交付订单凭证。第三方的留存期限另按其服务条款核实。[生命周期依据](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)

## 2. Queue 与消费 Worker 为什么需要

**Queue** 是云端任务队列，负责保存已经提交的待办任务，安排投递和失败后的重新投递。它保存 jobId 等小记录，不装整张照片。

**消费 Worker** 是运行在 Cloudflare 的后端程序，负责领取队列中的任务，调用火山方舟、保存结果、更新状态。Pages Functions 接收用户操作；消费 Worker 执行较长任务。两者都是程序，不是雇人，也不需要再找两家供应商。

流程：用户提交 → 后端确认付款及照片审核 → Queue 接收 jobId → 消费 Worker 生图 → R2 存结果、KV 更新状态 → 页面查询展示。

只有成功入队后，才可承诺用户关页不取消后台生图。Queue 会重新投递，所以必须检查同一 jobId/attemptId 是否已经处理，不能重复扣次。平台的排队 Header 只影响该次 API 等待，不替代本产品任务队列。[执行期限与队列建议](https://developers.cloudflare.com/workers/runtime-apis/context/#waituntil)

消费者从单并发开始，再按实际 IPM/RPM/并发配额调整。本站队位只作估算；不承诺 Queue 严格先进先出或知道火山内部队位。积压明显过长时暂停新收费，先履行已付订单。

如果抠图放在浏览器，关页后只能保证后台生图继续；抠图和卡片合成需用户回页完成。如果要求整个处理链都在关页后完成，就要选择后台可调用的抠图服务。

推荐保留本增项，估计 **0.5–1 天，待确认**。这不等于必须先开 Workers 付费套餐；但上线前须核查免费额度和队列保留期，不能默认无限。

## 3. 价格倒计时与支付找回

截止点只写一次：`2026-10-31T00:00:00+08:00`，对应 UTC `2026-10-30T16:00:00Z`。即 10 月 30 日 23:59:59 仍在早鸟期，10 月 31 日 00:00:00 起恢复 5.9 元。

前端获取 serverNow、cutoffAt、amountFen、quoteExpiresAt；按服务器时间校准后每秒刷新。显示总小时数，不能按 24 取模；超过 99 小时显示三位。刷新、换手机、改本地时钟不重置；切回前台和付款前重新取价。客户端倒计时不能决定最终收费。

截止前支付成功的订单，之后回来照常领取。早鸟未付报价跨过截止点时失效，提示新价并让用户重新确认；已付用户走查单，不能让其再付一次。旧 2 元链接在截止后仍被付款的情况，先核实再退款，不能偷偷补扣。平台支付时间字段及旧链接下架能力须真单验证；缺字段时转人工，不用收到回调/查询结果的时间冒充支付时间。

**支付找回**包含两个问题：付的是哪只猫、浏览器丢了以后怎么继续。payId 把平台订单绑定 testId；私密找回凭证让用户在原浏览器、换浏览器或备用域名恢复原结果/订单。它不是注册登录，也不是直接接入微信商户支付。相同订单反复确认，只返回原权益。

支付绑定、查询、找回和重复付款处理合计估计 **0.75–1 天**。本次取消库存后不再开发 N、余量扣减或防超卖。

## 4. 答题页现在可以先开发

可以在另一个项目开始，不必等支付、生图或页面风格全部确定。先将题目/角色数据、算分逻辑、接口请求、页面样式分开。稳定 optionId 不随洗牌改变；返回或刷新保持原顺序；评分算法和 TIE_BREAK 直接复用定稿。

首轮用固定假数据跑通：答题 → 免费结果 → 免费卡保存。将“已付款、未付款、排队、失败、成功”的返回值做成测试数据，等真实服务接好后替换接口层。假付款只能用于开发环境，生产环境不能信任 localStorage 的解锁字段。

最小接口约定（路径是建议，业务字段先固定）：

| 接口 | 输入 | 核心返回 |
|---|---|---|
| POST /api/sessions | 来源、quizVersion | testId、私密凭证 |
| GET /api/config | 无 | serverNow、cutoffAt、amountFen、quizVersion、五色配置 |
| POST /api/results | 凭证、testId、optionId 答案、猫名 | 服务端 roleId、六轴、publicId、结果文案 |
| POST /api/checkout | 凭证、testId | payId、amountFen、quoteExpiresAt、支付链接 |
| GET /api/checkout/:payId | 凭证 | 未支付/核对中/解锁/已使用/退款状态 |
| POST /api/recover | 私密口令 | 对应 testId、结果及订单状态 |
| POST /api/photos | 凭证、压缩照片 | photoId、审核状态、错误码 |
| POST /api/jobs | 凭证、payId、已通过审核的 photoId | 原子创建或返回已有 jobId |
| GET /api/jobs/:jobId | 凭证 | stage、估算队位、图片访问地址、expiresAt |
| PUT /api/jobs/:jobId/rating | 凭证、1–5 分 | 当前评分 |
| POST /api/refund-requests | 凭证、payId、评分、reasonCode、说明 | requestId、处理状态 |
| POST /api/events | 白名单事件及匿名参数 | 接收结果 |

错误统一返回 code、message、retryable；前端按错误码处理，不靠解析中文提示。价格、角色、剩余次数均不采信前端输入。支付/生图供应商密钥不进入前端包。

卡片渲染的输入固定为：templateId、猫名、publicId、roleId、金句、主图地址、backgroundId、AI 标识配置；输出 PNG。尺寸是模板参数，后续换风格无需改支付或算分。

## 5. 最近照片选不到：需要做哪些兼容

这通常不是生图模型问题。可能涉及系统照片选择器、应用只能访问部分照片、云端原图未下载、HEIC 解码或页面错误处理。网页不能承诺控制用户相册排序，也不能自行扫描其所有照片。

网页首版使用系统文件/照片选择器，允许 `image/*`，不强制 capture 为相机。accept 是选择提示，不代替后端验证。Android 官方选择器支持按时间浏览及部分云端照片；浏览器或微信具体界面仍由系统/容器决定。[MDN 文件选择说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file)、[Android 照片选择器](https://developer.android.com/training/data-storage/shared/photo-picker)

| 情况 | 页面行为与直接可用文案 |
|---|---|
| 用户点取消 | 保留上一张照片和订单；不弹“上传失败” |
| 最近照片没出现 | 帮助文案：“试试切换到相册或最近项目；仍找不到，可先在系统相册打开照片，再回来选择。” |
| 云端照片等待 | 选择器尚未交回文件时不假报上传进度；提示：“云端照片可能需要先下载，请保持网络畅通。” |
| 应用仅获部分相册权限 | 提示检查微信/浏览器的照片权限；允许重新选择授权照片，不要求本产品读取整个相册 |
| HEIC/HEIF | 能解码则转 JPEG；否则：“这张照片暂时读不了，请上传 JPG 或截图。” |
| 方向/预览异常 | 按 EXIF 校正后压缩；确认猫脸完整才上传 |
| 大图/低内存 | 限制原图体积，分步解码压缩；失败提示换普通尺寸图片，不直接白屏 |
| 网络中断 | 保留 File/预览并重试同一上传；重新打开页面后必要时重新选图 |
| 再选同一张图 | 必须再次响应选择，不因为文件名相同而无反应 |

界面分别显示“正在读取照片…”、“正在上传…”、“正在检查照片…”。拒绝与服务故障用不同文案；审核不通过立即删除暂存照片，不进生图。

真机至少验：iPhone Safari、iPhone 微信、Android Chrome、Android 微信；每类测试最近拍摄、截图、相册普通图、云端图、HEIC、取消、重复选图、慢网。这里的原生照片选择器资料用于理解系统机制，不代表 H5 能调用 iOS 原生 PhotoKit 或 Android Jetpack API。

完整 HEIC 转码支持另估 **0.5–1 天，待确认**；首版可以先采用能力检测与换图兜底。

## 6. 两种导出、尺寸、透明背景与去水印

**双导出**：同一生成结果，导出完整角色卡，或导出独立角色头像。不是让模型出两张。

推荐：生成主图 1:1、2048×2048；角色卡用竖版 9:16、1080×1920；头像用 1:1、1080×1080。16:9、4:3 都是横版；3:4 适合竖版图文卡，9:16 更适合手机壁纸。尺寸尚待用户决定。

角色卡让主体位于中间；顶部约四分之一给手机时钟留白，文字避开上下裁切区。手机屏幕并非都为 9:16，不承诺完全免裁切。头像按圆形裁切预留边距，避免耳朵或脸被平台裁掉。

处理链：Seedream 生成一张 → 抠图一次得到透明 PNG 主图 → 前端铺透明或五种颜色 → 合成头像/卡片。五色不是五次生图；PNG 后缀也不等于拥有透明通道。透明预览用棋盘格，导出仍需真实 alpha；相册显示黑/白底不代表文件一定不透明。

抠图候选：

| 路线 | 已核实的能力与边界 | 首版判断 |
|---|---|---|
| rembg＋明确选定的本地模型 | rembg 代码 MIT；模型许可独立；其当前默认模型可能有商业授权要求 | 不能按“库免费”推定全部模型可免费商用；Python/ONNX 后端通常需额外运行环境 |
| U²-Net/U²-NetP | 官方仓库 Apache-2.0；提供 176.3MB/4.7MB 预训练文件 | 可作为开源候选；小模型适合先测移动端，但毛边/装饰保留效果未验证 |
| @imgly/background-removal | 可浏览器内处理，AGPL-3.0 | 不能直接当作闭源商业项目的无条件免费组件，需遵守许可或另谈授权 |
| 托管 BiRefNet API，例如 fal | 官方模型页标 Commercial use，支持图像背景移除 | 开发较省；新增供应商、费用及留存条款，需确认；页面占位价格不可当成真实预算 |

来源：[rembg](https://github.com/danielgatis/rembg)、[U²-Net 模型](https://github.com/xuebinqin/U-2-Net)、[U²-Net 许可](https://github.com/xuebinqin/U-2-Net/blob/master/LICENSE)、[IMG.LY](https://github.com/imgly/background-removal-js)、[fal BiRefNet](https://fal.ai/models/fal-ai/birefnet/v2)。具体模型权重与转换文件也须记录来源和许可。

五天期限下，建议先用代表样图验抠图质量，再在轻量浏览器方案和托管 API 之间定一种；不在本周自建完整推理平台。至少覆盖毛须、蝙蝠翅膀、幽灵袍、头纱、帽子和小道具。抠图失败不能以重新扣费生图代替。

**去水印分两种**：品牌字/搜索口令由 canvas 绘制，可用开关控制，不需要模型擦除；供应商 AI 标识及必要隐式标识不作为去除对象。若只是想统一 AI 标识样式，先核实供应商是否允许相应输出模式及重新标识，不靠擦除原图来实现。LaMa 等图像修补模型属于技术候选，但本产品没有必要为自己后画的品牌字加一次推理；也不能假定修补不会改变猫脸或毛纹。[LaMa 项目](https://github.com/advimman/lama)

抠图可能丢掉角落标识，canvas 重编码也不能保证保留元数据。透明/换底/卡片导出都要重新核验显式与必要隐式标识；可用前端 PNG 元信息写入或后端轻量封装补全，不重新生图。所有导出派生图继承主图到期日，不因换背景重置七天。[官方标识说明](https://www.cac.gov.cn/2025-03/14/c_1743654685896173.htm)

品牌显隐是否开放尚待确认；两档必须同规则，不加早鸟角标。五色先预留 bg-1…bg-5，等页面风格确定再给颜色值。

## 7. 用户评分与退款需要多少开发

已确认使用用户 1–5 分评分，不做 AI 相似度评分。评价可跳过；1–2 分出现退款申请入口，理由必填，重复申请合并。低分只触发申请，不自动退钱，不增加一轮生图。人工只核实退款，不补生。

后台记录订单号、jobId、评分、理由、申请时间和处理状态。申请待核实时禁止新生图；退款方式按爱发电账户实际支持的流程执行，本次没有验证可用的自动退款接口。24 小时是核实承诺，不是到账承诺。

简版评分＋申请＋状态记录估计 **0.25–0.5 天**，可用现有平台后台/数据导出人工处理，不必自建完整售后后台。删掉人工补生流程会抵消一部分工作，通常不需因此额外加一天。完整后台管理或自动退款另需 **0.5–1 天以上，待确认**；自动 AI 相似度评分与校准另估 **1–2 天，首版不做**。

## 8. 埋点用什么，调用量在哪里查

**埋点**是记录用户到了哪一步，例如开始答题、看结果、点付费、付款核实、生成成功、导出、评分。分析工具把记录汇成漏斗图；供应商账单不能告诉你有多少人答到第八题就走了。

首版推荐 PostHog Cloud，只手动发送关键事件，关闭自动全量捕获、会话录屏及敏感属性采集。初始化 SDK 前先消费并移除恢复链接中的私密片段；统一过滤事件的完整 URL、查询串及片段，只上传白名单参数/页面名，避免默认上下文泄露口令。其当前产品分析免费额度为每月 100 万事件，普通小活动可以先用免费档；不是 100 万用户。上线前测试大陆网络与拦截情况，后端支付/生图台账不能依赖客户端埋点。[PostHog 定价](https://posthog.com/pricing)

准备：创建一个项目，开发接入项目 key，制作“开始测试→完成测试→看结果→点付费→确认付款→生成成功→导出”的漏斗。用户评分和退款另记事件。前端 key 不能代替支付/生图的服务端密钥。只做漏斗接入和基础图表估计 **0.25–0.5 天**。

| 要查什么 | 第一查看位置 | 本产品应补的记录 |
|---|---|---|
| API 调用量/用量/账单 | 火山方舟控制台用量统计、账单、对应监控 | 模型、attemptId、平台 requestId、状态、耗时、图片张数 |
| 哪单失败、是否重试 | 受控的订单/任务台账及 Cloudflare 日志 | payId→jobId→attemptId 关联、错误码、次数 |
| 图片最终效果 | 成品预览及用户评分 | 图片键、评分、reasonCode、退款申请 |
| 用户在哪流失 | PostHog 漏斗 | 关键业务事件，不存照片、名字、口令 |

火山官方有 [用量统计](https://docs.volcengine.com/docs/ark/usage-statistics?lang=zh) 和 [推理用量查询 API](https://docs.volcengine.com/docs/ark/get-inference-usage-api?lang=en)，但不同模型的图片张数/成功率维度须登录账户核对，不能默认通用 token 查询接口完整覆盖 Seedream 图片任务。

区分 API 请求次数、成功图片数、付费订单数、最终交付数；技术重试、429、退款都会让它们不同。最初用供应商控制台＋可按 jobId 搜索的日志即可，不急于自建复杂监控平台。自己的 /api/jobs 查询接口属于本产品后端，不是额外采购的一家“接口查询供应商”；仍消耗请求配额。

## 9. 供应商、费用与上线渠道

**首发建议：网页＋爱发电。** Cloudflare 部署网页，不等于向微信提交小程序；爱发电负责其平台内的付款流程。不是“网页收费都免审”：创作者/商品仍受收款平台规则约束，直接接微信支付另有商户及场景资格。非对话式生图也不能据此认定豁免全部 AIGC 义务。

微信官方普通商户接入要求列出个体工商户、企业等主体；最新权限表同时列出“小微商户”可支持小程序支付。小微商户是正式进件身份，不是个人收款码；能否走服务商、类目是否匹配、AppID 能否绑定均需实际审核。不能说“个人绝对没有任何路径”，也不能说“个人小程序可以直接接个人收款码”。[接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015459512)、[权限表](https://pay.wechatpay.cn/doc/v3/merchant/4015459054)

小程序还涉及备案、平台类目和发布审核，当前五天期限及无备案状态下，不把它作为首发依赖。[工信部 APP 备案通知（含小程序分发）](https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2023/art_920db564162e4312916a01bed6540ad8.html)

产品对外提供生成服务时，网站/应用备案、生成式 AI 服务相关手续和标识要求应分别核实。调用有备案的模型不自动证明应用所有手续已经齐备；“不是对话产品”也不是统一豁免条件。[生成式人工智能服务管理暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)、[生成内容标识说明](https://www.cac.gov.cn/2025-03/14/c_1743654685896173.htm)

## 10. 周期变化与下一步

1. 现在即可另建产品项目，先完成答题、结果及免费卡；本项目不动产品实现。

3. 用代表样图决定抠图路线，确认卡片尺寸和五色；透明头像是本次主要工期风险。
4. 再接后台生图、评分申请、埋点、双导出，最后做手机真机验证。

取消库存和装饰动画省下一部分工作；评分退款新增约 0.25–0.5 天；透明抠图、许可与手机兼容新增约 **0.5–1.5 天，待确认**，若自建后端推理通常还会更长。原双导出 0.5–1 天估算只覆盖前端合成/保存，不包括新抠图服务。以上模块可能共享联调时间，不能简单相加当承诺。
