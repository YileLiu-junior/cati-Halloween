## 一、产品背景（已定，不要推翻）

**产品**：万圣节猫咪人格测试。主人做 10 道选择题测猫咪性格 → 免费看到你家猫是 16 个万圣节角色中的哪一个 → 可付费上传一张猫咪照片，AI 生成该角色 cos 的 3D 黏土玩偶形象，并渲染成一张含专属 ID + 宠物名字的万圣节角色卡 → 导出分享到小红书/朋友圈。

**硬约束**：
- 今天 2026-10-26（周一），万圣节 10-31（周六），目标 10-29~30 上线蹭节前流量，节当晚 19-22 点是传播高峰
- 个人开发者、无企业资质、无备案；主阵地小红书（微信对测试类 H5 链接是打击类目，引流靠"搜索口令"不靠链接）
- vibe coding 风格：**最懒可行**，任何超过半天开发量的设计都要标注出来让我确认
- 传播逻辑：免费档也必须有可分享的简版卡片（角色名+猫名+ID），付费墙锁的是"AI 形象完整卡"这个增量，不能锁死"晒"的入口

**已锁定的技术方案**：
- 前端 Vite 单页 + Cloudflare Pages Functions（后端）+ KV（订单/计数）+ R2（存图），自定义域名 + 备用域名
- 生图：火山方舟 Seedream 4.0 图生图，约 0.2 元/张，单次付费出 1 张；限流指标为 IPM/RPM/并发（账号级配额，可用请求头 `X-Ark-Max-Wait-Timeout-Ms` 让平台排队，前端轮询结果）
- 照片必须机审（阿里云内容安全，约 0.005 元/张）后才能进生图链路
- 收款：爱发电（6% 抽成），有开放 API（user_id + token）可轮询查询订单（含金额/时间/买家昵称/留言字段）；无微信商户号、无个人收款码方案
- 分享卡：前端原生 canvas 手绘导出 PNG（不用 html2canvas），微信内保存靠"长按图片"
- 合规：生成图必须带"AI 生成"标识；照片隐私文案（仅用于本次生成、不用于训练、7 天删除）；不做对话式 AIGC

**已锁定的定价**：免费测评+简版卡 → 早鸟 2 元（限量 N 份）解锁完整版 → 常规价 5.9 元。单次生成 1 张图（成本约 0.4 元/单，可承受"失败免费重试 1 次"级别的售后）。

**已定稿的测评系统**（评分机制、题型、角色方案按此执行，不要重新设计；你能读文件就参考 `quiz-design.md`，不能读就按此摘要）：
- 六条属性轴：电量/贴贴/胆量/戏精/干饭/好奇，每题选项对属性 ±3 分，只用于结果页雷达图展示，不参与匹配
- 10 道单选题（下班开门迎接、开饭反应、半夜跑酷、快递箱/陌生人、像人时刻、摸摸敏感度、玩耍风格、抢地盘、外出体检、镜头感），每题 4 个选项
- 匹配 = 每个选项直接给若干角色加分（主+2 / 签名选项+3 / 副+1），总分最高者胜，平局按固定顺序表取先
- **每题的 4 个选项必须随机排序后展示**（平衡性前提，不可省略）
- 16 个角色：小幽灵咪、小僵尸咪、电锯咪、木乃伊咪、小护士咪、吸血鬼咪、科学怪咪、海盗咪、小丑咪、月光新娘咪、女巫咪、南瓜咕噜咪、狼人咪、蝙蝠咪、石像鬼咪、法老王咪（每个角色已配好人设 3 短句 + 卡面金句 + 生图 prompt）
- 结果页（免费）：翻牌悬念动效 → 角色立绘 + 称号 + 六边形雷达图 + 3 条性格短句 + 金句 + 宠物名 + 专属编号 ID + 简版可保存卡
- 付费解锁后：上传照片 → 生成角色 cos 的 3D 黏土玩偶形象 → 渲染进完整角色卡

## 二、你的任务

### 任务 1：方案快速审查（占输出 ≤15%）
只挑**会影响交互设计落地**的漏洞与风险（例如：无登录体系下订单与结果的绑定方案、爱发电解锁的可靠性、免费档与付费档的边界模糊点等），每条给一句修改建议。不要泛泛的产品评价，不要推翻已锁定项。最多 10 条。

### 任务 2：详细交互功能设计文档（主交付物）

要求：可以直接照着写代码的程度。流程用步骤表/状态机表述，不写实现代码（关键处可给伪代码）；所有文案直接给可用文本，不要写"此处放文案"；总篇幅控制在 3500 字左右，**付费流程与异常兜底两节是重点，占一半篇幅**。

需要覆盖：

1. **完整用户旅程图**：从小红书笔记/搜索口令进入 → 答题（10 屏）→ 翻牌出结果（免费）→ 付费墙 → 支付 → 上传照片 → 生成 → 渲染完整卡 → 两种导出（导出完整角色卡 / 仅导出生成形象）。每个节点标注：页面名 / 用户动作 / 系统行为 / 数据变化（localStorage 与 KV 各存什么）。
2. **页面清单与逐页设计**：每页给元素、状态（加载/空/错误）、关键文案、跳转关系。至少含：落地页、答题页（复用模板）、翻牌结果页、付费墙、支付等待/回流页、上传页、生成排队页、成品页、导出分享引导。
3. **付费流程细节（重点）**：
   - 付费墙出现时机与文案（2 元早鸟的"限量 N 份"怎么呈现与倒数）
   - 爱发电跳转-支付-回流的完整链路：如何携带订单标识跳转、付款后如何引导返回、订单确认机制（API 轮询 + "我已付款"手动兜底按钮的轮询策略与频控）
   - 订单状态机：未支付 → 已支付待确认 → 已解锁 → 已使用；幂等性（同一订单重复确认不重复发号）；会话绑定（刷新/换浏览器后凭链接或口令找回结果与订单的方案——无登录体系）
   - 早鸟限量的实现与超卖处理（KV 计数器；超卖后的兜底话术与处理）
   - 支付失败/中途放弃/重复付款的用户路径
4. **照片上传流程**：压缩与格式限制、机审拒绝后的文案与重试路径、隐私提示文案全文、上传失败重试。
5. **生成流程**：提交 → 排队（第 N 位展示）→ 生成中 → 完成；超时与 API 限流的重试策略；**生成失败的用户补偿**（免费重试次数与退款指引的取舍，结合 0.2 元/张成本）；生成结果不满意的重生成规则。
6. **导出与分享**：两种导出物（完整角色卡 / 仅生成形象）的尺寸、水印策略差异（2 元档 vs 5.9 档的差别怎么体现）、canvas 生成方式、保存引导文案（微信长按保存）、分享话术与"搜索口令"回流设计。
7. **异常场景兜底矩阵（重点）**：用表格逐行列出"场景 | 用户看到什么 | 系统做什么 | 文案"。至少覆盖：支付中断/放弃；支付成功但回调没确认；重复付款；照片审核不通过；生图超时；生图 API 配额耗尽；生成结果翻车（不像用户的猫）；用户中途退出后隔天回来；免费用户想测第二只猫；微信内置浏览器兼容问题；早鸟售罄。
8. **数据埋点清单**：为验证漏斗指标（测试完成率>60%、付费按钮点击>15%、留资/付费转化>5%）需要埋的最小事件集（事件名/触发时机/参数）。
