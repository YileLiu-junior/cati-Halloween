# 头像付款、后台交付与退款操作

更新：2026-10-30。当前代码已通过本地测试，尚未发布本次生产更新。真实退款尚未完成。

退款流程同日修订（44 项接口测试、49 项浏览器测试通过）：未确认付款的订单不再能冻结交付；用户可撤回待审核申请；同一订单最多两次售后申请；审核期间仍可保存已生成的头像；移除从未写入的 `error` 状态并补齐待补充/处理中私信文案。

## 当前用户路径

1. 用户选择猫或狗的角色并上传照片。
2. PETI 保存订单、照片关联、价格、Prompt、参考图路径和模型配置快照。
3. 付款链接同时携带 `custom_order_id` 和旧版兼容留言。
4. 爱发电在新标签页打开，原 PETI 页面保留。
5. Webhook 先持久保存交易号，后台再向爱发电查询权威订单。
6. 金额、商品、型号、数量和网站订单号全部匹配后，订单进入后台生成队列。
7. 独立 Worker 消费任务，读取私有照片及对应猫狗参考图，调用一次 Seedream。
8. 成品保存到私有 R2，订单记录交付时间。
9. 爱发电付款账号收到订单入口与完成提醒。
10. 用户从原页面或私信链接查看进度、保存头像、提交售后。

正常路径不需要复制爱发电订单号。未确认付款的异常路径仍保留手动核对入口。平台没有已验证的付款成功自动回跳，本实现使用新标签页和私信返回。

## 一致性与故障处理

- 网站订单、真实支付交易、生成任务、生成尝试和退款申请分别保存。
- 支付通知先入库，队列发送失败由每分钟维护补投。
- 每分钟扫描最新支付页，并推进一个历史页，覆盖早创建、晚付款的订单。平台每页最多查询 100 条。
- 同一交易不能认领两个网站订单。重复付款保存独立台账，只授予一份生成权益。
- 金额或商品不匹配时不生成。已确认属于本单的实际付款仍保存，供退款核对。
- 生成认领采用数据库条件更新。租约过期后，旧执行者不能继续启动收费调用。
- 明确 429 拒绝允许用户重试一次。超时、响应损坏、保存失败和调用后中断不自动重发收费请求。
- 调用前中断可以重新排队。已保存成品但订单更新中断时，只补交付，不重跑模型。
- 每次尝试保存阶段、HTTP 状态、供应商请求编号、耗时、错误码和预定成品路径。
- 当前直接交付模型出图（白底）。图层拆分、透明合成及相关 CLI 参数已于 2026-10-31 移除，后台和本地工具都不再加载 PNG 像素处理库。
- 本轮构建中，后台包由拆分前的 651.98 KiB 减至 77.93 KiB；此数字不代表实际 CPU 或内存用量。
- 图片上传和成品仍受 R2 七天清理规则约束。财务及售后记录不随图片清理删除。
- 私信结果未知时保留人工核对，不自动反复发送。后台核实未发后可补发。

## 私信入口与访问权限

`/avatar.html` 只展示当前订单及售后，不要求恢复免费测评。

签名凭证放在 URL 片段中，读取后移出地址栏，保存于当前标签页会话。API 通过请求头接收凭证。页面禁止缓存、索引及发送来源地址。

凭证只授权对应订单的状态、成品和售后。它不能访问原始照片或其他订单。变更订单 `link_version` 可撤销旧链接。链接有效期至少覆盖订单创建后的 90 天，成品领取期限仍为交付后的七天且受对象实际保留期限制。

付款链接由他人代付时，私信发往真实付款账号。订单关联不等于核实操作者的自然人身份。

## 用户退款路径

1. 在原定制窗口或私信订单页打开“申请退款或核对付款”。
2. 选择未交付、生成失败、重复付款、图片问题或付款未识别。
3. 填写可选说明和通知方式。
4. 提交后查看同一页面中的审核进度。

生成明确失败可立即申请。超过十分钟未交付可申请全额退款。其他售后问题也可随时提交，不以补充邮箱或付款号作为正常订单的门槛。

未确认付款的订单只能选择“付款未识别”或“重复付款”，其他原因返回 409。这样用户不会在付款前提交申请、把订单冻结成付款后一直不生成的状态。

待审核或待补充信息时可以撤回。撤回不消耗审核，但计入次数上限；撤回后订单恢复排队，已生成但被拦下的成品直接补交付，不重复调用模型。

同一订单最多两次售后申请（首次 + 一次复核），重复付款核对不计数。达到上限后需要走爱发电私信人工处理。

系统延迟提示从本站确认付款起计算，因为平台本次查单仅返回 `create_time`，不能将订单创建时间假称为付款成功时间。通知迟到时，用户仍可立即提交“付款未识别”申请。审核应按真实付款凭证核对超时资格，不要求重新等待十分钟。

提交申请后暂停新增生成和重试。已提交供应商的任务可能继续返回；晚到图片先保留。满足超时条件的未交付申请，不能仅因图片晚到而驳回。审核期间已生成的头像仍可查看和保存，只有退款批准、处理中或已退款后，普通订单接口才不再提供成品下载。

首次审核目标为 24 小时，需运营者实际处理。此目标不是渠道到账承诺。

## 管理员审核

打开 `/avatar-admin.html`，填写 `AVATAR_ADMIN_SECRET`。凭证仅保存在当前页面内存，不存入浏览器持久存储。

1. 选择退款申请。
2. 查看付款台账、实际金额、申请说明和生成记录。
3. 对缺失台账的旧订单，点击“核实付款”。服务端查询爱发电，不信任手动填写的已付款标记。
4. 图片问题可鉴权查看原始照片和成品。退款期间保留的晚到成品也可核对。
5. 执行批准、驳回并填写理由，或请求补充信息。
6. 批准后通过已核实的渠道处理资金，并登记处理中。
7. 实际成功后，填写退款渠道、凭证编号及精确金额，登记已退款。

批准只更新审核状态，不自动标记资金退回。未核实交易或金额不一致时禁止登记退款。重复付款退款只处理多付交易，保留原交易权益。原付款已退款时，仍可继续处理后来发现的多付交易；不会因此恢复已退款的生成或下载权益。

用户可补充资料后重新提交。驳回后可从订单页提交复核（受两次上限约束）。用户撤回的申请显示为“用户已撤回”，不能继续审核，但订单立即恢复生成。退款和付款核对均保存审计记录。
